## Workflow YAML

Final intended `.github/workflows/release.yml`:

```yaml
name: Publish to GAR

on:
  workflow_dispatch:
    inputs:
      bump:
        description: "Lerna bump override (default: auto-detect from-package vs prerelease)"
        required: false
        type: string

jobs:
  publish:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: actions/checkout@v4
        with:
          ref: templ-for-bwa
          fetch-depth: 0

      - name: Install Corepack
        run: npm install -g corepack

      - uses: actions/setup-node@v4
        with:
          node-version-file: .nvmrc

      - uses: google-github-actions/auth@v2
        with:
          workload_identity_provider: ${{ vars.GAR_NPM_WIF_PROVIDER }}
          # NO service_account — direct WIF per AI-920

      - uses: google-github-actions/setup-gcloud@v2

      - name: Install
        run: yarn install --immutable

      - name: Configure GAR auth
        run: |
          token="$(gcloud auth print-access-token)"
          cat > "$HOME/.yarnrc.yml" <<EOF
          npmScopes:
            blue-water-autonomy:
              npmRegistryServer: "https://us-central1-npm.pkg.dev/blue-water-autonomy-operations/bwa-npm/"
              npmAlwaysAuth: true
              npmAuthToken: "${token}"
          EOF
          cat > .npmrc <<EOF
          @blue-water-autonomy:registry=https://us-central1-npm.pkg.dev/blue-water-autonomy-operations/bwa-npm/
          //us-central1-npm.pkg.dev/blue-water-autonomy-operations/bwa-npm/:_authToken=${token}
          //us-central1-npm.pkg.dev/blue-water-autonomy-operations/bwa-npm/:always-auth=true
          EOF

      - name: Determine bump
        id: bump
        run: |
          set -euo pipefail
          version="$(jq --raw-output '.version' lerna.json)"
          if [ -n "${{ inputs.bump }}" ]; then
            echo "bump=${{ inputs.bump }}" >> "$GITHUB_OUTPUT"
            echo "args=" >> "$GITHUB_OUTPUT"
          elif npm show @blue-water-autonomy/html-eslint-plugin@"${version}" \
                 --registry=https://us-central1-npm.pkg.dev/blue-water-autonomy-operations/bwa-npm/ \
                 >/dev/null 2>&1; then
            echo "bump=prerelease" >> "$GITHUB_OUTPUT"
            echo "args=--preid bwa" >> "$GITHUB_OUTPUT"
          else
            echo "bump=from-package" >> "$GITHUB_OUTPUT"
            echo "args=" >> "$GITHUB_OUTPUT"
          fi

      - name: Publish
        run: |
          yarn lerna publish --no-private ${{ steps.bump.outputs.args }} \
            --registry=https://us-central1-npm.pkg.dev/blue-water-autonomy-operations/bwa-npm/ \
            ${{ steps.bump.outputs.bump }} --yes
```

### Design decisions (rationale)

- **`workflow_dispatch` only**: matches the issue spec. Tag-push triggers (`on: push: tags: ['v*']`) are tempting given the ref-pin caveat but are out of scope per the issue's literal spec; leave that to a follow-up.
- **`ref: templ-for-bwa` on `actions/checkout`**: the workflow file itself ends up on `templ-for-bwa`, but `workflow_dispatch` can run from any ref the user picks in the UI. Pinning to `templ-for-bwa` ensures the publish job always operates on that branch's tree regardless of which ref triggered it. This also matters for satisfying the WIF `attribute_condition` if it's eventually allowlisted to `refs/heads/templ-for-bwa`.
- **`google-github-actions/auth@v2`**: the issue body specifies `v2`. Latest stable is `v3` (released Sep 2025); `v3` requires Node 24+ on the runner. **Implement may upgrade to `v3` if desired** — both versions support direct WIF (no `service_account:`) per upstream docs. Recommendation: stick with `v2` for fidelity to the issue spec; revisit in a follow-up if `v3`'s features (improved error reporting, token caching) become useful.
- **`google-github-actions/setup-gcloud@v2`**: same as above — latest is `v3.0.1` but `v2` matches the issue spec and is fully supported.
- **`workload_identity_provider: ${{ vars.GAR_NPM_WIF_PROVIDER }}`**: store the AI-920 output (`projects/<PROJECT_NUMBER>/locations/global/workloadIdentityPools/github-actions/providers/github-oidc-bwa-npm`) as a **GitHub Actions repository variable** (not a secret — the value is non-sensitive). This avoids hardcoding the project number. If `vars.GAR_NPM_WIF_PROVIDER` isn't yet set at Implement time, document this as a one-time setup step in the PR description so the maintainer adds it before triggering the workflow.
- **Both `.yarnrc.yml` (Yarn Berry) and `.npmrc`**: this repo uses Yarn Berry (`.yarnrc.yml`, `packageManager: yarn@4.9.1`). Lerna-lite still shells out to `npm` for `npm show` and `npm publish` under the hood (depending on `npmClient` config — here `npmClient: "yarn"`, but lerna-lite's `npm show` check uses npm regardless). Writing both files mirrors the existing `./publish` script and covers all code paths. `npmAlwaysAuth: true` is added to the yarnrc per Google's Yarn Berry docs.
- **Versioning logic preserved**: the `./publish` script's logic is exactly preserved — `npm show @blue-water-autonomy/html-eslint-plugin@<lerna.json version>` against GAR; existing → `prerelease --preid bwa`; missing → `from-package`. The `inputs.bump` override lets an operator force a specific lerna bump (e.g., `patch`, `minor`).
- **`--registry` passed twice**: once to `npm show` (during the check) and once to `lerna publish`. The `.npmrc` is written before the check, so both paths resolve the registry correctly even if a flag is ever dropped accidentally.
- **`--yes` flag**: confirmed supported by `@lerna-lite/publish` v4.11.1 (current repo dep) per upstream README. Skips the interactive confirmation prompt.
- **`fetch-depth: 0`**: lerna-lite needs full git history to compute changed packages for `from-package` mode. Matches the existing manual workflow (the dev would have full history locally).
- **`permissions: id-token: write`**: required for the OIDC token exchange in `google-github-actions/auth`. `contents: read` is fine (no commits/tag pushes from this workflow; lerna publish with `from-package` doesn't bump versions in git).

### Lerna behavior notes worth verifying first run

- `lerna publish from-package` does NOT create git tags or commits — it just publishes whatever is on disk that's missing from the registry. Safe for a workflow with `contents: read`.
- `lerna publish prerelease --preid bwa` DOES bump versions and create git tags/commits by default. With `contents: read`, the local-only bump will succeed but pushing back to the repo will fail. The current `./publish` script doesn't pass `--no-push --no-git-tag-version`, suggesting the existing manual flow either pushes from the dev's machine (with full write perms) or accepts the push failure silently. **For CI**, Implement should add `--no-push --no-git-tag-version` (or grant `contents: write` and configure git identity). Recommended: add `--no-push --no-git-tag-version` to keep `contents: read` and avoid bot commits. This is a **deviation from the literal issue YAML** but is necessary for correctness; flag in PR description.
